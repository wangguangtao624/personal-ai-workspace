# 沉淀经验

仅从当前可读取的对话、资料与成果提取反馈；其他聊天不会自动可见。区分用户原话、最终确定内容与 AI 的推测。结合最终稿及修改过程，提出精简的候选经验，标明来源、日期、适用范围（本次、项目、某类任务或通用）、原因及待确认状态。

一次性要求不要自动推广为长期偏好。向用户展示候选并取得确认后，才把长期经验写入已确认记录或建议更新相关 Skill、模板；若用户要求更正或撤销，记录更正依据和时间，避免声称系统自动维护了版本历史。实际成果和原始资料保持原样，规则冲突时以当前明确指令及适用范围为准。

若用户已经明确确认某条经验及范围，可直接记录该条；无法确定范围时先标待确认。当前 CLI 的 `--scope` 仅接受 `general` 或已建项目 ID，不支持“某类任务”作为独立范围。某类任务的经验可写明其适用条件并放在对应工作流的经验记录中；不应把它标为无条件通用。读取项目级经验时仍须检查任务类型。下一次同类任务检索适用的已确认经验，并根据新反馈继续调整。
