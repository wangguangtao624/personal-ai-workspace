# 固件测试工作流

根据任务检索相关岗位背景、项目、芯片和板卡、固件版本、变更说明、接口、环境、需求、历史缺陷与已确认的项目规则。优先使用用户明确指定的资料；列出实际来源、版本、资料冲突和缺口，避免把其他项目或过期版本的结论套入本任务。

根据现有资料拟定测试范围、前置环境、功能与边界/异常、变更回归、风险和验收依据。用例应能表达编号、前提、步骤、预期、实际、状态及证据；未知内容标记待确认。用例设计、建议的操作和真实执行结果分开，未提供执行证据时不得标记通过或失败。

遇到可能影响设备或数据的实际烧录、硬件操作或外部系统写入，按任务授权和现场条件执行；不因检索到文档就假定操作权限。产出引用来源，明确适用项目和固件版本，用户提出的新经验可交由 capture-feedback 工作流整理。
