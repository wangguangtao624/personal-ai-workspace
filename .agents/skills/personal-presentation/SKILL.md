# 个人演示文稿工作流

明确本次受众、目的、资料和输出需求；检索相关项目资料、用户确认的偏好、可用模板与已认可案例，检查项目、受众、权限和模板版本是否适用。当前明确要求优先；仅将适用的已确认偏好用于该任务。找不到模板或无法访问资料时如实说明，不伪称已经使用。其他项目资料不作为本次事实。

在有现成 PPTX/POTX 模板且适用时，尽可能保留其母版、布局、视觉样式与可编辑性。按资料生成结构与内容，重要事实可追溯到来源，缺失的数字不编造。使用环境中适合的演示文稿工具制作，并按工具的要求渲染和检查每页溢出、可读性及一致性。说明实际完成的验证和无法验证的部分。

迭代期间记录用户的修改与版本；最终定稿后可调用 capture-feedback 工作流，区分一次性要求、某类汇报偏好及普遍偏好。不要把聊天中的所有修改自动视为长期规则。
