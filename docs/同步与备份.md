# 同步与备份

## 双设备日常流程

使用受控的私有仓库，给 GitHub 账号启用双重验证。先确认个人资料与公司资料分别允许保存、发给模型、上传个人 GitHub 和备份。**在不知道授权状态时不要把公司资料推送到个人仓库。** 不要把密码、令牌、API 密钥或登录会话纳入 Git。

在每台电脑上使用前先查看工作区和远端状态，获取已提交的最新版本，再录入和整理。结束后检查具体变更，确认只包含允许同步的资料，再提交和推送。断网时可本地收集；联网后再同步。任一设备有未提交内容时，先保存并检查，避免覆盖。

建议的人工 Git 操作：

```powershell
git status
git fetch origin
git pull --ff-only
git status
```

`pull --ff-only` 遇到分叉会停止；先检查两台设备的状态。冲突时保留两份内容，人工比较并解决；不要强制推送或覆盖。整理完内容并审阅后再选择需要的文件提交。**若数据目录被 `.gitignore` 排除，它不会自动同步**；需设计并检查单独的获授权知识仓库，或显式选择允许提交的文本。仅代码仓库的同步不等于知识同步。

### 单独同步知识文本（需要你自行配置）

本项目默认忽略 `data/`，防止首次上传代码时带上个人信息。要在两台电脑同步知识文本，可以另建一个私有知识仓库，放在项目目录之外，并在两台电脑分别克隆；下面以 `D:\personal-ai-data` 为例，实际路径自行选择：

1. 在 GitHub 建立第二个**私有**仓库；给账号启用双重验证。配置 Git 登录凭据。此仓库应仅包含你有权同步的内容。
2. 两台电脑各自克隆该知识仓库到本机目录；第一次在其中运行 `python app.py --data D:\personal-ai-data init`（使用程序所在目录中的 `app.py`）。仅第一次生成的初始化内容需要提交；另一台先拉取已有内容，再运行 `init`，该命令不会覆盖已有背景。
3. 在知识仓库根目录创建 `.gitignore`，至少写入 `attachments/`、`outputs/`、`.env`、`*.key`、`*.pem`。这些目录不会随 Git 同步；音频和生成文件应通过独立加密存储备份和恢复。请按实际数据继续排除不应上传的内容。
4. 使用程序时始终指定 `--data D:\personal-ai-data`；每次先在知识仓库执行 `git status`、`git fetch origin`、`git pull --ff-only`。处理完毕后检查 `git status` 和 `git diff`，只对明确允许上传的文件执行 `git add -- <文件>`，再 `git commit` 和 `git push`。
5. 每台电脑的目录路径可不同，但都应指向同一个获准的知识仓库。工作资料不允许进入个人 GitHub 时，应另外放在公司批准的位置；不要写进个人知识仓库。

上述流程需手动配置，项目不会替你创建知识仓库、自动同步或加密。忽略规则不会移除之前已经提交的文件；已泄露密钥应及时撤销。

## 独立备份

GitHub 提供版本和远端副本，但误删除、错误提交、账号问题也可能影响同步后的数据。至少保留一个与 GitHub 独立的加密、可版本恢复的副本，位置可为另一服务或异地硬盘。备份应覆盖：

- 知识文本和仓库历史；
- 模板、PPT 成果和附件；
- 原始录音、转写及其关联索引；
- 必要的程序配置、恢复说明和加密密钥恢复方法。密钥不要放在同一份不加密备份中。

大型音频和视频通常另存于获授权的加密文件存储，知识文件只保存可用的文件编号、来源与位置；如采用 Git LFS，先确认容量、流量及费用。定期在一个新目录实际恢复文本、模板和一段音频，检查内容、关联和密钥可用，再记录恢复结果。

如果敏感信息已进入 Git 历史，后来删文件并不能确保历史和其他副本被清除，应尽快撤销相关凭证并按服务提供方的清理流程处理。
